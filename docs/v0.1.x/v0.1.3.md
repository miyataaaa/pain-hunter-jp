## 変更詳細

### 修正1: 過去データ由来クラスタの `opportunity_score` が 0.0 になるバグ（bugfix）

**問題の構造**

`clusterer.py` は過去 `LOOKBACK_DAYS`（7日）分の `normalized` データをマージしてクラスタを構築する。
一方 `scorer.py` は当日生成の `extracted` データのみを `pain_lookup`（`question_id` → `ExtractedPain` の辞書）に読み込んでいた。

そのため、過去日付の `normalized` データに含まれる `question_id` は `pain_lookup` に存在せず、
それらのペインが属するクラスタの各スコアフィールドがすべてデフォルト値 `0.0` のまま確定していた。

```
クラスタ内 pains = [past_pain_A, past_pain_B, today_pain_C]
                       ↑               ↑
                   pain_lookup に存在しない → スコア計算スキップ
```

クラスタ全体の `opportunity_score` は構成ペインのスコア平均で算出されるため、
過去データが多い（＝繰り返し性が高い）クラスタほど過小評価されるという、
設計意図と真逆の結果を招いていた。

**修正内容（`src/scorer.py`）**

`_load_past_extracted()` 関数を追加し、`run()` 内で当日分と合算して `pain_lookup` を構築する。

```python
def _load_past_extracted(today: date) -> list[ExtractedPain]:
    """過去LOOKBACK_DAYS日分のExtractedPainを読み込む。"""
    ext_dir = Path(config.DATA_DIR) / "extracted"
    results: list[ExtractedPain] = []
    logger = logging.getLogger(__name__)
    for i in range(1, config.LOOKBACK_DAYS + 1):
        past_date = today - timedelta(days=i)
        for past_file in sorted(ext_dir.glob(f"{past_date.isoformat()}*.json")):
            try:
                with open(past_file, encoding="utf-8") as f:
                    items = json.load(f)
                for item in items:
                    results.append(ExtractedPain(**item))
            except Exception as e:
                logger.warning("過去extractedデータ読み込みエラー: %s  error=%s", past_file, e)
    return results
```

`run()` での呼び出し箇所:

```python
# 修正前
pain_lookup = self._build_pain_lookup(extracted)

# 修正後
today = date.fromisoformat(date_str[:10])
past_extracted = _load_past_extracted(today)
all_extracted = extracted + past_extracted
self.logger.info("extracted: 当日%d件 + 過去%d件", len(extracted), len(past_extracted))
pain_lookup = self._build_pain_lookup(all_extracted)
```

**効果**

- `clusterer.py`（normalized）と `scorer.py`（extracted）が参照するルックアップ期間が揃い、
  `question_id` の不一致によるスコア 0.0 が解消される。
- 過去データ由来のクラスタも正しくスコアリングされ、繰り返し性の高い課題が上位に上がるようになる。
- `data/extracted/` の過去ファイルが存在しない場合（初回実行など）は `warning` ログのみで継続するため、
  後方互換あり。

**`clusterer` との対称性**

```
clusterer.py  → data/normalized/ の過去7日分をマージ
scorer.py     → data/extracted/ の過去7日分をマージ（今回追加）
                ↑ これにより両者が同じ期間のペインを参照する
```

### 改善2: カテゴリ一覧を業務・生活実務・嗜好の3グループに再編（feat）

**背景**

v0.1.2 までのカテゴリは「コンサル・士業の業務効率化」「フリーランス・個人事業主の事務作業」
「中小企業のIT・DX」という3ジャンルで構成されていた。
実運用の結果、以下の課題が判明した。

- 企業法務・税金・保険・IT系カテゴリは「知識質問」の割合が高く、
  フィルタで弾かれる投稿が多い（構造的ペインが少ない）。
- 生活実務（家事・郵便・役所手続きなど）は消費者として自分も経験する課題が多く、
  ビジネスアイデアへの解像度が高い。
- ペット・コスメなど「パッション系」カテゴリはニッチSaaS・コミュニティ型の
  アイデアシーズになりやすい。

**変更内容（`src/scraper/chiebukuro.py`）**

カテゴリを「業務・フリーランス系（6）」「生活実務系（4）」「嗜好・パッション系（2）」
の計12カテゴリに再編。

## データフロー（v0.1.3時点）

```
Yahoo!知恵袋（12カテゴリ）
     │
     ▼
[Step1] Scraper        → data/raw/YYYY-MM-DD_HHMM.json
     │  ★ 業務・生活実務・嗜好の3グループ12カテゴリ
     ▼
[Step2] Filter         → data/filtered/YYYY-MM-DD_HHMM.json
     │
     ▼
[Step3] Extractor      → data/extracted/YYYY-MM-DD_HHMM.json   ← Claude API
     │
     ▼
[Step4] Normalizer     → data/normalized/YYYY-MM-DD_HHMM.json
     │                   NormalizedPain.fetched_date をセット
     ▼
[Step5] Clusterer      → data/clustered/YYYY-MM-DD_HHMM.json
     │  ← 過去7日分の normalized も読む
     │  PainCluster.date_count を計算
     ▼
[Step6] Scorer         → data/scored/YYYY-MM-DD_HHMM.json
     │  ← 当日 extracted + 過去7日分の extracted を読む（★今回追加）
     │  cluster.date_count で recurrence_score を算出
     ▼
[Step7] IdeaGenerator  → data/ideas/YYYY-MM-DD_HHMM.json       ← Claude API（上位3クラスタのみ）
     │
     ▼
[Step8] Report+Notify  → reports/YYYY-MM-DD_HHMM.md + ntfy.sh
```
