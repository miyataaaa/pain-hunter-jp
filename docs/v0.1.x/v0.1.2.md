## 変更詳細

### 修正1: `recurrence_score` の `date_count` ハードコード解消（バグ）

**問題の構造**

`scorer.py` の `_calc_recurrence_score` は「クラスタが何日分のデータから構成されているか」を
`date_count` として受け取り、繰り返し性ボーナスを算出する設計だった。

```python
# scorer.py — _calc_recurrence_score
size_score       = min(cluster_size / 10.0, 1.0)
recurrence_bonus = min(date_count / LOOKBACK_DAYS, 1.0)  # LOOKBACK_DAYS=7
return (size_score * 0.7 + recurrence_bonus * 0.3)
```

しかし実際の呼び出し箇所では `date_count=1` がハードコードされており、
`recurrence_bonus = 1/7 ≒ 0.143` で常に固定されていた。
「複数日にまたがって出現するクラスタほど高スコア」という設計意図が全く機能していなかった。

**原因**: `NormalizedPain` に取得日フィールドがなく、`PainCluster` 構築時に
各ペインが何日分に渡るか計算できなかった。

**修正内容**

4ファイルにまたがる連鎖的な修正。

#### `src/models.py`

```python
# NormalizedPain に fetched_date を追加
@dataclass
class NormalizedPain:
    ...
    fetched_date: str = ""  # 取得日 (YYYY-MM-DD)。Clustererでdate_count算出に使用

# PainCluster に date_count を追加
@dataclass
class PainCluster:
    ...
    cluster_size: int = 0
    date_count: int = 1   # 何日分のデータから構成されるか（recurrence_score算出用）
    ...
```

#### `src/normalizer.py`

`run()` で `normalize_one()` の後に実行日付をセット。

```python
n = self.normalize_one(pain, i)
n.fetched_date = date_str[:10]   # 追加
normalized.append(n)
```

#### `src/clusterer.py`

過去ファイル読み込み時、ファイル名の先頭10文字（`YYYY-MM-DD`）から `fetched_date` をセット。
旧フォーマットの JSON（`fetched_date` フィールドなし）はデフォルト値 `""` でデシリアライズされるため後方互換あり。

```python
file_date = past_file.stem[:10]   # 例: "2026-04-04"
for item in data:
    pain = NormalizedPain(**item)
    if not pain.fetched_date:
        pain.fetched_date = file_date
    results.append(pain)
```

`_build_clusters()` でクラスタ構築時に `date_count` を計算。

```python
date_count = len({p.fetched_date for p in pains if p.fetched_date}) or 1

cluster = PainCluster(
    ...
    cluster_size=len(pains),
    date_count=date_count,   # 追加
    ...
)
```

#### `src/scorer.py`

ハードコードを `cluster.date_count` に置き換え。

```python
# 修正前
cluster.recurrence_score = _calc_recurrence_score(cluster.cluster_size, date_count=1)

# 修正後
cluster.recurrence_score = _calc_recurrence_score(cluster.cluster_size, cluster.date_count)
```

**効果**: 過去7日分のデータが蓄積されるにつれ、複数日にまたがって出現するクラスタの
`date_count` が増加し、`recurrence_bonus` が正しく機能するようになる。
最大 `date_count=7`（LOOKBACK_DAYS）のとき `recurrence_bonus=1.0`。

### 修正2: workflow の `git add` から `logs/` を除外（バグ）

`.gitignore` に `logs/` が含まれているにもかかわらず、
`.github/workflows/daily.yml` の Commit results ステップで `git add logs/` していた。
これが GitHub Actions の "Commit results" ステップ失敗の原因。

```yaml
# 修正前
git add data/ reports/ logs/

# 修正後
git add data/ reports/
```

---

### 改善3: GitHub Actions を1日2回実行に変更

JST 03:00 の1日1回から、JST 03:00 / 15:00 の1日2回に変更。

```yaml
# 修正前
- cron: '0 18 * * *'    # JST 03:00 = UTC 18:00

# 修正後
- cron: '0 6,18 * * *'  # JST 03:00 = UTC 18:00 / JST 15:00 = UTC 06:00
```

1日2回実行することで、翌日以降の `date_count` 算出精度も向上する
（同日2回分が同一 `fetched_date` でまとめられる）。

## `recurrence_score` の算出ロジック（v0.1.2確定版）

```
recurrence_score = size_score * 0.7 + recurrence_bonus * 0.3

  size_score       = min(cluster_size / 10, 1.0)
                     # 10件で上限1.0。件数が多いほど高い

  recurrence_bonus = min(date_count / LOOKBACK_DAYS, 1.0)
                     # LOOKBACK_DAYS=7。7日間全てに出現で上限1.0
                     # date_count は PainCluster 内の fetched_date のユニーク数
```

**スコア例**:

| cluster_size | date_count | size_score | recurrence_bonus | recurrence_score |
|---|---|---|---|---|
| 3 | 1 | 0.30 | 0.143 | 0.253 |
| 3 | 3 | 0.30 | 0.429 | 0.339 |
| 5 | 5 | 0.50 | 0.714 | 0.564 |
| 10 | 7 | 1.00 | 1.000 | 1.000 |
