## ココナラパイプライン設計

### 目的

ユーザーが「人力でお金をもらっている作業」＝ **構造的ニーズが実証された需要** を
ソースに使う。知恵袋（ペインの存在確認）とは補完的な情報源になる。

### データフロー

```
ココナラ（8カテゴリ）
     │  販売実績順
     ▼
[Step1] CoconalaScraper     → （未保存 / dry-run 時はスキップ）
     │  requests + BeautifulSoup
     │  Nuxt.js SSRのHTMLを直接パース
     ▼
[Step2] Analyzer            → data/coconala/{date}.json
     │  Claude API（バッチ10件ずつ）
     │  is_automatable / task_type / builder_fit / saas_price_suggestion を付与
     ▼
[Step3] Report              → reports/coconala_{date}.md
     │  自動化可能案件の一覧表を生成
     │  ntfy.sh でサマリー通知（オプション）
     ▼
     通知
```

## 実装詳細

### `src/coconala/scraper.py`

#### HTML構造（実際のページを確認済み）

ココナラは **Nuxt.js SSR** を採用しており、`window.__NUXT__` はJavaScript関数形式のため
JSONパース不可。サーバーサイドレンダリング済みのHTMLを直接パースする。

カテゴリによって2種類のカードレイアウトが存在する：

| レイアウト | カード要素のクラス | 使用カテゴリ例 |
|-----------|-----------------|-------------|
| 一覧ビュー (List) | `c-serviceListItemList_inner` | IT系・ライティング系 |
| ブロックビュー (Block) | `c-serviceBlockItemBlock_inner` | Web制作・ビジネス代行系 |

各フィールドのセレクタ（一覧ビュー）：

| フィールド | セレクタ |
|-----------|---------|
| タイトル/URL | `a[class*='c-serviceListItemColContentHeader_overview']` |
| 説明文 | `a[class*='c-serviceListItemColContentHeader_catchphrase']` |
| 価格 | `a[class*='c-serviceListItemColContentFooterPrice_price'] strong` |
| 評価スコア | `span[class*='c-serviceListItemColContentFooterPriceRating_score']` |
| レビュー数 | `span[class*='c-serviceListItemColContentFooterPriceRating_count']` |
| 出品者名 | `div[class*='c-serviceListItemColContentFooterInfoUser_name'] a` |

ブロックビューは同様のクラス階層で `c-serviceBlockItemContent*` プレフィックスを使用。

#### robots.txt

`/categories/` への制限なし（確認済み）。リクエスト間隔は `SCRAPE_INTERVAL_SEC`（デフォルト2秒）。

---

### `src/coconala/analyzer.py`

Claude API（`claude-sonnet-4-20250514`）に出品データをバッチ10件で送信し、
以下フィールドを付与：

| フィールド | 型 | 説明 |
|-----------|----|------|
| `is_automatable` | bool | Python/LLM/API で自動化できるか |
| `automation_summary` | str | どう自動化できるか（1〜2文） |
| `task_type` | str | 10文字以内の作業名 |
| `automation_difficulty` | int 1-5 | 実装の難易度 |
| `builder_fit` | int 1-5 | Python/LLM/APIで作れる度 |
| `monthly_demand_estimate` | str | high/medium/low |
| `saas_price_suggestion` | int | 月額SaaS化した場合の推定価格（円） |

`is_automatable: true` の判定基準の主な例：
- データ入力・転記・変換、文書作成・テンプレート埋め
- リサーチ・情報収集・まとめ、翻訳・校正・リライト
- SNS投稿作成、データ分析・レポート生成

## バグ修正詳細（スクレイパー初期実装の問題）

### 問題1: カテゴリIDが全て不正

初期実装の CATEGORIES に設定されていたIDはすべて誤りだった。

| カテゴリ名 | 旧ID（誤） | 新ID（正） | 備考 |
|-----------|-----------|-----------|------|
| システム開発・アプリ開発 | 91 | 232 / 237 | 91は「ダイエット相談」カテゴリ |
| Webサイト制作 | 92 | 500 | 92は「ファッション相談」カテゴリ |
| ビジネス代行 | 200 | 13 | 200は404（存在しない） |
| データ入力 | 180 | 429 | 180は404（存在しない） |
| 記事作成 | 30 | 372 | 実際のID確認前に推測で設定 |
| 翻訳・通訳 | 31 | 290 | 同上 |
| SNS運用 | 120 | 311 | 同上 |

**調査方法**: 実際のカテゴリ一覧ページ (`/categories`) のHTMLから全カテゴリのIDを抽出して修正。

---

### 問題2: フレームワーク誤認（Next.js → Nuxt.js）

初期実装は「Next.js製サイト」と誤認し、`<script id="__NEXT_DATA__">` からのJSON抽出を試みていた。
実際には **Nuxt.js** (`window.__NUXT__`) を使用しており、かつJavaScript関数形式（`window.__NUXT__=(function(a,b,...){...})`）のためJSONパース不可。

**修正**: `_extract_next_data()` 関数と `_parse_listings_from_next_data()` を削除し、
HTML直接パースのみに統一。

---

### 問題3: CSSセレクタ不一致

初期実装のセレクタ（`li[class*='c-serviceCard']`, `div[class*='ServiceCard']` 等）は
実際のDOM構造と完全に不一致だった。実際のHTMLをダウンロードして確認（1.5MB）し、
正しいクラス名 `c-serviceListItemList_inner` / `c-serviceBlockItemBlock_inner` を特定した。

## よく使うコマンド

```bash
# 動作確認（保存・通知なし）
python -m src.coconala.main --dry-run

# 1カテゴリあたり10件に絞って実行
python -m src.coconala.main --limit 10

# 特定カテゴリのみ
python -m src.coconala.main --categories "IT・システム開発"

# 通知スキップ
python -m src.coconala.main --skip-notify
```
